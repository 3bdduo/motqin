# مُتقِن — منصة متابعة مذاكرة طلاب الثانوية والبكالوريا

مشروع Next.js واحد يجمع الفرونت إند والباك إند مع بعض (API Routes)، وقاعدة البيانات على
Supabase (سحابية بالكامل، مفيش أي حاجة لوكال). جاهز للرفع على Vercel.

---

## 1) تجهيز قاعدة البيانات (Supabase) — مرة واحدة فقط

1. روح على https://supabase.com وسجّل دخول (أو أنشئ حساب مجاني).
2. اعمل **New Project**. اختار اسم وباسورد لقاعدة البيانات واحفظهم.
3. لما المشروع يخلص التجهيز، روح لـ **SQL Editor** من القائمة الجانبية.
4. افتح ملف `supabase/schema.sql` الموجود في هذا المشروع، انسخ محتواه كامل،
   الصقه في الـ SQL Editor واضغط **Run**. ده هيعمل كل الجداول والصلاحيات (RLS) تلقائيًا.
5. روح لـ **Authentication -> Providers** وتأكد إن **Email** مفعّل (مفعّل افتراضيًا).
   من الأفضل كمان إيقاف "Confirm email" من **Authentication -> Settings** عشان
   حسابات الطلاب اللي هتنشئها كأدمن تشتغل فورًا من غير تأكيد إيميل.
6. روح لـ **Authentication -> Users -> Add user** وأنشئ أول حساب أدمن (إيميل + باسورد).
7. انسخ الـ **User UID** بتاعه، وارجع لـ **SQL Editor** وشغّل:

```sql
insert into public.profiles (id, role, full_name)
values ('ضع-الـ-UID-هنا', 'admin', 'اسمك');
```

8. روح لـ **Project Settings -> API** وسجّل عندك 3 قيم هتحتاجهم بعدين:
   - `Project URL`
   - `anon public` key
   - `service_role` key (سري جدًا، متشاركوش مع حد)

---

## 2) تجربة المشروع محليًا (اختياري)

```bash
npm install
cp .env.example .env.local
# افتح .env.local وحط القيم الثلاثة اللي جبتها من Supabase
npm run dev
```

افتح `http://localhost:3000` وسجّل دخول بحساب الأدمن.

> ملحوظة: تشغيل المشروع محليًا هو للتجربة بس على جهازك. البيانات نفسها مش
> لوكال أبدًا، هي مخزنة على Supabase، فأي حد يفتح رابط الموقع بعد الرفع (من أي مكان)
> هيشوف نفس البيانات مباشرة.

---

## 3) الرفع على GitHub ثم Vercel

### أ) رفع المشروع على GitHub

```bash
git init
git add .
git commit -m "Initial commit - Motqin platform"
git branch -M main
git remote add origin https://github.com/USERNAME/motqin.git
git push -u origin main
```

### ب) الربط مع Vercel

1. روح على https://vercel.com وسجّل دخول بحساب GitHub بتاعك.
2. اضغط **Add New -> Project** واختار الريبو اللي رفعته.
3. Vercel هيكتشف إنه مشروع Next.js تلقائيًا، سيبه على الإعدادات الافتراضية.
4. قبل الضغط على Deploy، افتح قسم **Environment Variables** وضيف المتغيرات الثلاثة:

   | Name | Value |
   |---|---|
   | `NEXT_PUBLIC_SUPABASE_URL` | Project URL من Supabase |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon public key |
   | `SUPABASE_SERVICE_ROLE_KEY` | service_role key |

5. اضغط **Deploy** واستنى دقيقة أو اتنين.
6. هتاخد رابط زي `https://motqin.vercel.app` — الموقع ده شغال أونلاين ومتاح لأي حد
   من أي مكان، مش لوكال هوست خالص.

### تحديثات لاحقة

أي تعديل تعمله في الكود، اعمله `git push` بس، وVercel هيعيد النشر تلقائيًا.

## 4) استخدام المنصة

- **الأدمن** يدخل من نفس رابط الموقع (`/login`) بحساب الأدمن اللي أنشأته في الخطوة 1،
  وهيتحول تلقائيًا للوحة التحكم.
- من لوحة التحكم يقدر: يضيف طلاب جدد (بيتحدد لهم إيميل وباسورد دخول)، يحدد نظام كل
  طالب (ساعات مذاكرة، مواد، مواعيد دروس)، يضيف تاسكات يومية، يعمل امتحانات شهرية،
  ويتابع تقارير كل طالب.
- **الطالب** يدخل بنفس الرابط بالإيميل والباسورد اللي أنشأهملهم الأدمن، وهيشوف
  صفحته الرئيسية (عبارة تحفيزية + نسبة إنجاز اليوم + تاسكات اليوم).

## 5) ملاحظات تقنية مهمة

- **الأمان**: كل جدول محمي بـ Row Level Security — الطالب يشوف بياناته هو بس،
  والأدمن يشوف ويتحكم في كل حاجة. مفتاح `service_role` يُستخدم فقط داخل
  الـ API Routes على السيرفر (لإنشاء حسابات الطلاب)، وأبدًا في كود المتصفح.
- **الوضع الداكن/الفاتح**: زرار التبديل موجود في كل الصفحات، ويحفظ اختيار المستخدم.
- **التصميم**: بُني خصيصًا بدون أي درجة من اللون البنفسجي، بألوان teal/emerald
  وamber وcoral، وخط Tajawal العربي، ومتجاوب بالكامل مع الموبايل.
- **الإشعارات**: حاليًا يتم تحديثها كل 30 ثانية داخل التطبيق (polling) عند فتح
  الجرس. ممكن لاحقًا تفعيل Realtime من Supabase لو حبيت تحديث لحظي.
- **استعادة كلمة المرور**: تستخدم نظام الإيميل المدمج في Supabase Auth، فلازم
  يكون الإيميل المسجل للطالب صحيح وقادر يستقبل رسائل.
- **حماية إجابات الامتحان**: التصحيح يتم على السيرفر، وواجهة الطالب لا تجيب
  إلا نص السؤال والاختيارات فقط (مش الإجابة الصحيحة). في نسخة MVP هذه، صلاحية
  القراءة على جدول `exam_questions` مفتوحة لأي مستخدم مسجّل دخول على مستوى
  قاعدة البيانات، فطالب متمرّس تقنيًا يقدر نظريًا يستدعي الجدول مباشرة ويشوف
  الإجابة الصحيحة. لو حبيت تقفلها تمامًا، ابعتلي وهضيف دالة/View تُخفي عمود
  `correct_option_index` عن الطلاب تمامًا.
